# Urban Water Supply System Simulator

Консольная имитационная система водоснабжения (вариант 48). Реализация состоит из
серверного приложения и отдельного TCP-клиента-наблюдателя.

## Архитектура

- `water_supply_system` — сервер симуляции. Он загружает конфигурацию, запускает
  прежние рабочие процессы (`network`, `dispatcher`, `district`, `pipe`, `sensor`)
  и управляет модельным временем.
- Внутри сервера сохранены POSIX shared memory и семафоры: это минимизирует
  изменения предметной логики и синхронизации процессов.
- `src/external/tcp.c` — отдельный процесс-ретранслятор. События, сформированные
  сервером и его рабочими процессами, поступают в него через pipe и далее
  транслируются всем подключённым TCP-клиентам.
- `water_client` — отдельная программа-наблюдатель. Она подключается к серверу
  и выводит получаемые события. Можно одновременно запустить несколько клиентов;
  их отключение и повторное подключение не останавливает симуляцию.

TCP-клиент получает поток событий с момента подключения, без истории событий,
произошедших до подключения. Сервер поддерживает до 64 одновременных клиентов.

## Сборка

Требуется Linux, GCC с поддержкой C99 и GNU Make.

```bash
make
```

Сборка создаёт два исполняемых файла: `water_supply_system` и `water_client`.

## Запуск

Сначала запускается сервер:

```bash
./water_supply_system <config_file> [delay_ms] [max_time] [seed] [bind_ip] [port]
```

Параметры:
- `config_file` — файл конфигурации (обязательный);
- `delay_ms` — задержка между тиками, по умолчанию 500 мс;
- `max_time` — число тиков, по умолчанию 100;
- `seed` — начальное значение генератора случайных чисел, по умолчанию 1;
- `bind_ip` — IPv4-адрес интерфейса сервера, по умолчанию `0.0.0.0`;
- `port` — TCP-порт сервера, по умолчанию `5555`.

Затем на этом или другом компьютере запускается клиент:

```bash
./water_client <server_ip> <port>
```

Пример локального запуска:

```bash
# Терминал 1
./water_supply_system config.txt 500 100 42 0.0.0.0 5555

# Терминал 2 и, при необходимости, дополнительные терминалы
./water_client 127.0.0.1 5555
```

Для распределённого запуска вместо `127.0.0.1` указывается IPv4-адрес сервера.
Порт должен быть доступен по сети и разрешён межсетевым экраном.

## Отключение и завершение

- Клиент можно завершить через `Ctrl+C` или закрытием терминала. Это не влияет
  на сервер и остальные клиенты.
- После завершения клиента можно запустить его снова с теми же адресом и портом.
- Сервер завершает симуляцию по достижении `max_time`, при аварии или по `Ctrl+C`.
  После завершения сервер закрывает TCP-соединения, поэтому клиенты получают EOF
  и завершаются.
- Внутренние IPC-ресурсы очищаются прежним механизмом проекта.

## Логика симуляции и конфигурация

Формат `config.txt`, предметная модель, алгоритмы движения воды, работа датчиков,
моделирование потерь/задержек/дубликатов сообщений и стратегии `greedy` и
`sequential` сохранены без изменений. Полный поток событий по-прежнему выводится
в консоль сервера и в `simulation.log`, а также передаётся подключённым клиентам.

```bash
make clean
```

удаляет объектные файлы и оба исполняемых файла.
